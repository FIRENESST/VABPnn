# VABPnn Fabric 1.4.1

适用于 Minecraft Java **26.1**、Fabric Loader **0.19.3**、Fabric API **0.155.2+26.1.2**。Windows x64，需要 Minecraft 的 OpenGL 和 CUDA 都使用 NVIDIA GPU。工程 JVM 使用 JDK 26，Java 编译目标 25。

## 使用

将 build/libs/vabpnn-1.4.1.jar 放进目标实例的 mods；CUDA DLL 已打包，无需另外复制。目录中仅保留一个 vabpnn 模组，其他模组保留。默认处于**待命**：不会初始化 CUDA、分配 FBO/模型或弹出实时网络面板。进入世界后按 T 输入 **/vabpnn start** 才开始流程，默认进入人工示范训练；F8 才切换冻结评估 / 模型操作。

- **/vabpnn start**：启动流程；已运行时重复输入不会重新初始化或改变模式。F9 暂停后输入 start 可恢复原模式。
- **/vabpnn stop**：停止新帧采集和提交、释放模型操作、隐藏面板，恢复待命。已在处理的有限帧自然完成；参数留在显存以便再次启动，下一次 start 默认人工示范。退出世界也恢复待命，下一次进入须重新输入 start。
- **F6**：显示/隐藏独立模因传播窗口，GPU 取样和界面绘制均为 **5 Hz**；关闭窗口停止取样，计算流程继续。也可输入 `/vabpnn memes window [on|off]`。
- **F7**：启动后显示/隐藏独立实时网络面板；关闭面板停止 GPU 取样，网络保持运行。
- **F8**：人工示范训练 / 连续模型控制切换。模型控制冻结网络权重、Transformer multihead、AdamW 和 JEPA EMA，持续按后验与网络 k 执行，取消置信度阈值拦截；高贡献点、选点价值及 CSR 连接继续动态更新。再次按 F8 恢复人工示范学习。
- **F9**：已用 start 启动后，暂停 / 恢复采集和新帧训练。暂停会释放模型持有的输入；待命时 F6～F10 只提示先用 start，不会启动流程。
- **F10**：请求后台保存参数、AdamW 状态和训练计数。
- 流程初始化后每两分钟自动保存，正常退出时也保存；首次执行 start 后恢复已有模型。
- 1.4.0 / 1.4.1 共用模型，保存在 `vabpnn/models/release-1.4.0.bin`，v8 / 19 parts；分钟权重和 AdamW 独立追加，前 18 个 v7 部分布局不变。优先恢复本版；不存在时只读恢复 `release-1.3.0.bin`，再依次恢复兼容的 `release-1.1.0.bin`（1.1.0～1.1.2 共用）、`release-1.0.2.bin`、`release-1.0.1.bin`、`release-1.0.0.bin`，再依次只读迁移 `preview-1.0.0-pre-v2.bin`、`preview-1.0.0-pre-v1.bin`、`online-v3.bin`、`online-v2.bin`、`online-v1.bin`。保存只写本版路径，旧模型原样保留。不记录截图、视频或训练帧。
- 暂停、失焦、死亡、退出世界、普通菜单、管线失败或命令超过 0.5 秒失效时释放模型保持的输入。容器界面允许操作；切换世界保留权重、清空历史。
- 热键可以在 Minecraft 的按键绑定界面修改。全新模型没有游戏技巧，需要先给出示范；本版不是预训练游戏代理。

## 1.4.1：工程结构整理

本版只整理共享动作接口、工程文件分组、构建和验证入口，10 个 CUDA 实现文件及 JNI 桥接实现保持原样。PNN、CSR、秒 / 分钟图 Transformer、JEPA / 贝叶斯鼠标、优化器、训练频率和模式规则沿用 1.4.0；存档仍为 v8 / 19 parts，共用 release-1.4.0.bin，无新增参数或迁移。

- CUDA 算子仍在原 VS 工程；动作 / 位移 / 控制包单独放在 ActionContracts.h，JEPA 不再通过完整 Transformer 头间接取得这些接口。
- 原生测试移到 native/tests，性能基准移到 native/benchmarks；生产 JNI / checkpoint 路径保留。
- build.gradle 保留应用配置，gradle/native.gradle 管理原生打包，gradle/verification.gradle 管理窗口 / GL / Minecraft 验证。
- native/build-native.ps1 保留原命令行参数，native/build 下分出工具链、缓存、生产和验证脚本。缓存按真实本地头文件依赖校验，测试 / 基准可复用已链接程序；共享构建锁避免两次构建同时写 .pending 文件。
- gradlew.bat nativeTest 与 nativeBenchmark 提供统一验证入口；source JAR 递归携带整理后的原生源码、测试和脚本。VS 按接口、视觉、时序、表征、学习、连接和监控分组，补齐原来没有显示的模块。

结构与兼容说明：[1.4.1 工程结构](docs/1.4.1-project-structure.md)。

## 1.4.0：秒 / 分钟双时间轴

原秒轴保留最近 8 帧、以秒为单位的编码、图 multihead 与 CTMC 贝叶斯先验。新增独立的分钟图注意力分支：当前已观察分钟和前 7 个分钟槽，每帧同时参与预测，不需要等到一分钟才出结果。每槽保存时间加权的 15 项原始投票摘要，缓存不超过 8 个；断档不补造画面，重复时间戳不重复累计。所有状态留在显存，算子仍固定 1920×1024、16×16 线程块。

分钟分支为 8 维、2 个注意力头，新增 **1,117 个可学习参数**，包含节点/投票/时间编码、Q/K/V、图关系、分钟频率和衰减、贝叶斯证据与 k 融合头。有效人工示范对上一帧的因果缓存计算 BCE + k 交叉熵，经 AdamW 更新整个分钟分支；秒模型原有学习流程保留。没有示范时不把预测当标签；已有模型首次恢复时分钟证据与 k 权重为零，保持原秒模型行为，然后随真实示范学习。

F8、仅预测都冻结分钟权重和 AdamW；分钟历史、膜电位、高贡献点、候选位置价值、CSR 和模因传播照常推进。世界/模式复位与原秒轴一致，清空时间历史、保留学过的参数。`/vabpnn status` 新增秒数、分钟数、有效分钟槽数和分钟训练步数。

JEPA 鼠标数值新增 66 参数的贝叶斯残差头：以 15 项后验、先验和原 JEPA X/Y 速率为输入，学习真实鼠标示范的位移修正。它既能放大也能缩小或改变方向，初始为零，保留已有 JEPA 输出；原鼠标速度/单帧上限、X/Y 允许对象与模式规则保持不变。两项合计新增 1,183 个可学习参数，`/vabpnn status` 也显示贝叶斯鼠标训练步数。

新增持久部分 **14,216 字节**；v8 / VABPNND / 19 parts 文件大小 **522,109,692 字节**。前 18 个 v7 部分顺序和字节布局保持不变，可只读继承 1.3.0 的网络、优化器、动态选点和连接；1.2.0/1.2.1 仍只保留合并说明，不单独出包。机制和验证说明：[1.4.0 双时间轴](docs/1.4.0-time-axes.md)。

16 组 CUDA、独立分钟梯度、贝叶斯鼠标、窗口、实际 GL/JNI、1.3.0 只读继承和 Minecraft 26.1 全流程回归通过。满 8 槽、5 档共 2,560 帧独立压测最高 **8.6551ms**、超 10ms 为 **0**。GPU 占用新增 61,940 字节；另一 Minecraft 同时运行的功能回归存在 GPU 争用（算子峰值 27.153ms），未当作独立预算结果。用户释放负载后，同一最终 DLL 的单客户端 Minecraft 完整复测最高 **7.754ms**、超 10ms 为 **0**。详细数据与日志见上述 1.4.0 文档。

## 历史 1.3.0：贡献驱动的动态选点与连续控制

1.2.0、1.2.1 只保留 [说明文档](docs/1.2.0-1.2.1-notes.md)，不单独出包；功能合入本版。以下是当前模式规则，后文带旧版编号的测试与冻结行为属于历史记录。

| 模式 | 神经网络 / multihead / AdamW / EMA | 高贡献统计 / 选点 / CSR | 模型键鼠注入 |
| :--- | :--- | :--- | :--- |
| /vabpnn start 人工示范 | 在线学习 | 动态更新 | 关闭 |
| F8 连续模型控制 | 冻结 | 动态更新 | 持续执行新预测包 |
| /vabpnn start predict 或 predict on | 冻结 | 动态更新 | 关闭 |

F8 和仅预测的候选对象不再比较置信度阈值，而是直接在所有有效动作上执行后验 top-k 与原互斥规则。k=0 仍是模型选择休息，本帧继续输出有效新包。按住/释放、鼠标位移和滚轮继续由原执行器处理；聊天、暂停、失焦与过期包仍遵守已有输入上下文。

### 位置价值学习

原贡献统计只看实际脉冲投票，明亮像素更容易触发 LIF，暗处的贡献可能一直观测不到。本版保留原 LIF 和实际投票计算，另外为每个 16×16 块保留 8 个候选点，每五轮预测评估一次，共 61,440 个候选。它们直接使用该像素原有 RGB 三值权重计算未经过脉冲门控的潜在票，所以低膜电位不会阻止选点学习。

- 候选价值累计动作原始票数证据项的后验敏感度、投票多样性和对已选行动的支持；对比度与相邻观察的变化只作小幅辅助，不使用原始亮度作评分。
- 下一张有效人工示范到达时，用真实标签的 leave-one-neuron-out 交叉熵改善及动作命中，替换上一张候选观察的估计奖励。同一观察只算一次访问，不制造人工示范、不增加神经优化器步数。
- 每块保留价值均值、二阶矩和访问数，用有界不确定性加分探索候选；保留最佳候选，交替试探其曼哈顿 6 邻域及块内随机位置。价值随反馈改变，可重新定位。
- 全局选点同时考虑原最高命中点、实际贡献和候选价值；约 1/8 的名额用于空间探索，其他名额限制同一 64×64 区域的拥挤。最多仍为 256 个锚点，局部扇出 ≤4，长程半径 6，四种连接属性和 SpMV/CSR 结构不变。

F8/仅预测没有真实示范目标时，用冻结模型估计的动作敏感度继续更新结构价值与统计；不会把模型自己的预测当作正确示范。这里学到的是贡献位置价值，没有引入新的游戏奖励或更新被冻结的网络参数，是否改善实际游戏表现仍需示范与观察验证。

选点持久状态新增 **1,105,920 字节**，GPU 临时候选记录 **1,720,320 字节**；不存图像、不增加逐帧分配或图像读回。膜电位和像素算子仍固定 **1920×1024**，线程块 **16×16**；窗口的 120×64 块图仍只是状态摘要。选点和连接每五次预测刷新，F6/F7 取样频率及普通 Windows 窗口层级保持原有设置。

## 历史 1.1.2：冻结权重的仅预测模式

- 从待命直接进入：输入 **/vabpnn start predict**。从第一张提交到 CUDA 的帧起就冻结学习，不注入模型操作。
- 已在运行：输入 **/vabpnn predict** 或 **/vabpnn predict on**，进入仅预测；立即释放模型持有的键鼠，排除排队的旧指令。
- 输入 **/vabpnn predict off** 返回人工示范学习。**F8** 从仅预测进入原来的冻结评估 / 模型操作；再按 F8 返回示范。F9 暂停、start 恢复时保持当前模式，stop 或退出世界恢复待命。
- F6/F7 和聊天 / HUD 标记“仅预测 · 冻结 · 无操作”，显示模型建议对象、概率、阈值、预测鼠标 Δx/Δy 与滚轮；实际执行单独显示为零。仍可手动游玩观察模型对不同画面的反应。

冻结复用现有 CUDA evaluation 标记，覆盖像素三值/主权重、贝叶斯阈值与 k、JEPA 自监督和位移头、AdamW/EMA、坐标适配、高层/模因策略、排名变异与 SNN 贡献/连接学习；瞬态膜电位、时间历史、概率与模因包的传播/衰减继续。切换复用 F8 的帧边界：已经在 GPU 执行的旧模式帧可能先完成，旧排队指令被丢弃；首帧即只预测请用 start predict。

读取预测和键鼠注入采用两个独立状态。仅预测即使收到非零移动、跳跃、Ctrl/Shift、鼠标按键/位移或滚轮建议，也不会注入。模型路径仍为 release-1.1.0.bin，CUDA DLL 与 1.1.1 相同，不新增图像读回和逐帧 CUDA 分配。两个窗口保持普通 Windows 层级。


本版验证：已有两个窗口的渲染/开关检查通过，其中仅预测模式在输入不活跃时仍显示预测位移，执行位移为零。共享 CUDA 冻结逻辑的 GPU 哈希检查通过，确认权重、AdamW、EMA、主权重、模因知识和 CSR 学习状态不变；恢复示范后各学习器恢复。

Minecraft 26.1 临时世界通过从首帧 start predict、模式切换时释放 W/Ctrl/Shift/左键、真实 GPU 连续预测且各学习计数冻结、非空键鼠/位移/滚轮建议不注入、人工按键保持、重复指令幂等、F9 暂停与 start 恢复、predict off 恢复学习、F8 接管、15 路操作和 stop/退出复位。初轮在原有保存后块模式检查超时，失败日志保留；固定测试客户端 60 FPS 后全流程通过，生产 FPS 未变。复测时另一个 Minecraft 实例占满共享 GPU，日志峰值 51.998ms、超过 10ms 累计 544，本轮不作为性能达标结果。CUDA DLL 未修改；1.1.0 的独立基准属于历史验证，不代表当前共享 GPU 的时延保证。

日志在 build/predict-1.1.2-compile.log、predict-1.1.2-ui.log、predict-1.1.2-gpu-freeze.log、predict-1.1.2-minecraft.log（失败）与 predict-1.1.2-minecraft-retest.log（通过）；源码备份在 build/predict-1.1.2-backup。

## 1.1.0：独立的 5 Hz 模因传播窗口

## 历史：1.0.0-pre-v2 模因传播

模因采用明确语义的**8 维视觉/旧决策上下文 + 13 路动作证据**，每个 16×16 块保存一份学到的本地原型和一份进口活动包。13 路内容来自该块全部 256 个像素神经元的真实有符号票数 / 256，普通神经元也参与；上下文是当前 RGBA 的 RGB 均值、亮度方差，加上一帧模型的移动/交互/鼠标/跳跃四组后验，不使用当前或未来人工标签。画面仍按与原像素算子相同的中心采样规则投到 1920×1024。

只有因果配对的下一帧有效人工示范能更新本地知识、支持量、效用和可靠性。方向一致率按触发动作权重 1、未触发动作 0.25 计算；覆盖参与方向的权重占比。可信度为 max(0,2×agreement−1) × coverage × support/(support+16)。至少 16 个支持、可信度 0.1、上下文匹配 0.35 才能使用。上下文兼容为 exp(−8 维均方差/0.15²)，明显不匹配会重建本地支持。这是单原型预览，尚未实现多情境知识库。

**学到的知识与暂态传播包分开**。F8 停止可靠性、投影、像素和决策监督更新；JEPA 自监督仍按原规则继续。新的一帧真实匹配画面可重新激活已有知识、生成新活动序号，不增加支持或置信。转发保留原始来源、知识版本、活动序号和支持量；同身份重复转发不刷新年龄，不把转发当成新证据。活动使用真实秒制年龄，最长 2 秒、0.75 秒衰减、最多 8 跳；关闭来源后纯循环转发会过期。

传播与基础块控制同样每五轮刷新，在 CUDA 双缓冲中读取旧包。普通通道为四邻块；另从原有目标 CSR 的全部 256 行选择最多两个不同的实际长程来源块，排除自身、已计入的四邻块和重复来源。独立模式同时隔离邻接与长程；竞争模式在选路/选包排序前要求进口效用优于有效本地 +0.002；合作模式允许有限混合。本地占比至少 0.8，进口至多 0.2，无本地时也不把弱进口重新归一化放大。传输权重为 confidence × compatibility × exp(−age/0.75) × 0.9^hops；相反的本地知识不会自动变成全网同一个平均值。

每块新增独立 **13→4** 投影，共 **399,360 个权重**，零初始化。输入已经乘固定 0.15/13，权重限幅 ±1.5，额外潜在均值最大绝对值为 0.225；随后使用原高斯探索/tanh及四项控制边界。缓存实际生成旧控制所用的模因输入，只在控制真正重新生成时刷新。梯度复用原控制器旧优势和旧高斯噪声：−advantage×noise×cached_scaled_feature/exploration。投影有独立 AdamW 计步/矩和部分梯度，支持零权重启动后的非零更新；最佳策略、回滚/变异同步处理该分支。关闭模因后清动作/传播缓存并强制重算基础控制，不留下五轮旧动作。

- `/vabpnn memes`：查询完成帧的开关、活跃本地/进口、真实监督、投影、转发和长程选路计数。
- `/vabpnn memes on` / `off`：后台安全边界开关，不自动启动待命流程。
- `/vabpnn blocks independent` / `cooperate` / `compete`：同时控制模因通信模式。
- F7 面板新增“模因活跃”地图；选中块显示 13 路实际缓存输入、可信度、来源、跳数、年龄和支持/更新。保留鼠标 Δx/Δy、原像素与操作显示、缩放选块和不抢焦点。

新存档是 **v5 / VABPNNA / 256 字节头 / 17 parts**，旧 16 parts 布局完全保留，末尾追加 **7,495,792 字节**模因知识/投影/优化器/配置计数。进口包、未配对候选、部分梯度与动作缓存不保存。保存约 460,951,480 字节，仅写独立 pre-v2 路径；pre-v1/v3/v2/v1 均只读迁移。全文件 SHA256 校验在任何 GPU 参数覆写之前完成，恢复清理暂态活动与信用，保留学到的参数和 AdamW。

本版本聚焦模因传播，不包含 JEPA 鼠标训练样本平衡改动，也不将工程验证视作游戏任务正确率提升。原连续显存、固定分辨率、CSR/SpMV、时间图/Markov/Bayes、坐标分支和 13 路 Minecraft 执行继续使用。

## 历史：1.0.0-pre-v1 块级控制器

固定 1920×1024 的像素层与 16×16 CUDA 块继续使用。每个块新增一个轻量控制器，共 **7,680 个**；每个控制器将 16 项上下文线性映射到 4 项控制量，新增 **491,520 个可学习权重**，使用 AdamW 和 EMA 评分基线。上下文结合上一帧真实决策、块内脉冲/膜电位、贡献/方向一致率及有限邻块消息。

四项输出实际接入计算：阈值倍率 [0.8,1.2]，正负发放偏置 [-0.02,0.02]，秒制记忆倍率 [0.85,1.15]，像素监督学习倍率 [0.8,1.2]。偏置分别降低正阈值和提高负阈值；记忆倍率用于 exp(-dt/(tau*scale))。控制量每五轮预测重新生成，使用潜在高斯探索，经 tanh 和限幅得到有界控制量；关闭时四项恢复中性值。

学习遵守上一帧配对：先用当前到达的真实人工操作评价缓存的上一帧策略、上下文和探索量，再生成当前控制量，最后训练原像素/决策头并执行当前预测。至少 32 个有效示范后开始策略更新，每五个有效样本累计一次更新。F8 模型控制、无效标签、失焦和场景间断不提供该分支的监督；原 JEPA 自监督规则继续使用。

评分综合直接原始票数证据项的块级消融 BCE 改善、方向一致率和近期进步；活跃动作权重大于未触发动作。这里的消融固定了图上下文与历史先验，属于**直接证据贡献近似**，不等于重跑完整网络得到的因果贡献。方向一致率也不是整个游戏任务的准确率；自主行为质量仍需要实际示范评估。

默认启用协作模式。通信在 GPU 双缓冲中进行，邻域为曼哈顿距离 **1 个块**，每块最多读取四个有效邻块（边界更少）；该范围独立于原高贡献像素的曼哈顿距离 6。独立模式不读取邻块，协作模式有限混合邻块信息，竞争模式根据相对评分调节控制。命令在 CUDA worker 的安全边界生效，不引入渲染线程等待：

- `/vabpnn blocks`：查询已完成帧的开关、通信模式、评分帧和更新/排名/变异计数。
- `/vabpnn blocks on` / `off`：开关块级控制器。
- `/vabpnn blocks independent` / `cooperate` / `compete`：切换独立、协作、竞争模式。

每累计 128 个有效监督帧，GPU 对成熟块排名。参与要求至少 64 个累计示范、当前窗口至少 32 个样本、覆盖率至少 0.05。仅低于底部边界与中位数、考虑统计不确定性后仍落后、且自身没有改善的块累计低分窗口；连续三个低分窗口后才可变异。每次处理数量最多为合格块的 20%；并列低分不会任意惩罚。近期正向动作贡献冠军受保护，变异后冷却 256 个监督帧。

变异只作用于块级策略：以自身最佳策略为基础，协作模式也可采用较好的邻块策略，再收缩并加入有界小扰动，重置该策略的 AdamW 矩与步数。原像素三值参数、连接、决策头、JEPA 和坐标参数不被清空。排序、通信和训练均使用预分配显存，没有逐帧 CPU 排序、图像回读或显存分配。

预览存档采用 v4 格式（VABPNN9），原 v3 的 15 个 part 字节布局保持不变，追加第 16 个块级持久化 part（8,663,184 字节）。恢复保留策略、AdamW、配置和累计计数，清空暂态动作缓存、窗口和通信消息，避免重放旧示范。旧版 jar 以 `.jar.disabled` 保留，旧版模型不覆盖；测试世界的模型不用于正式实例。

## 30 Hz 人物坐标与预测

0.9.6 参考 AtomSpike sidecar 的 `LocalPlayer.position()`，在已启动流程的渲染回调中按固定 30 Hz 相位采样真实 XYZ。VABPnn 已在游戏进程内，直接通过 JNI 传递 40 字节时间戳、世界/玩家 epoch 和 double XYZ，无须绑定 AtomSpike 的 UDP 端口。渲染低于 30 FPS 时只采当前帧，不补发旧数据；Minecraft 模拟通常为 20 tick/s，相邻样本可能重复同一 tick 的坐标。

坐标与示范元数据一起绑定到提交的 FBO 画面，随显存队列丢帧或更换尺寸。CUDA 根据画面捕获时间检查因果性和 200 ms 有效期；缺失、未来时间、非有限值、越界坐标禁用坐标特征。换世界/重生、倒退时钟、超过 250 ms 的采样间隔或超过 128 blocks/s 的位置突变重置坐标原点和速度。

12 维输入为相对 XYZ（相对该段坐标历史起点，64 格尺度）、从坐标差和秒计算的平滑 XYZ 速度、绝对 X/Z 的正余弦位置编码、绝对高度及存在标记。double 位置先求差/编码，再转 float，保留远坐标处的小位移。两个线性投影分别将特征加入 15 个动作的条件对数似然比和 16 种 k 的 logits，仍经过原 CTMC 先验、贝叶斯、学习阈值、top-k 和互斥规则。原像素层固定 **1920×1024**，88,473,600 个三值参数及每像素的膜电位保持独立。

新增 **372 个可学习权重**，从零开始保持刚迁移的旧模型行为；沿用人工示范与 AdamW。训练使用缓存的上一帧坐标特征和此后发生的人工操作，不读未来坐标，不把模型控制作为示范。坐标支路的 AdamW 计数、矩与权重位于第 15 个存档 part；0.9.6 引入时保存在 online-v3.bin，正式版随完整模型保存到 release-1.0.0.bin。正式版会迁移旧动作维度，当前第 15 个 part 为 4,472 字节坐标参数/优化器；坐标历史仅存在于运行时。

`/vabpnn status` 增加 XYZ、坐标是否已到达预测和坐标训练步数；5 秒日志记录采样累计数和 GPU 消费时间戳。不会按 30 Hz 向聊天栏刷屏。命令启动、边玩边示范、F8 切换、F9 暂停、背包示范及实时面板继续沿用。

## 游戏内反馈

进入世界后，聊天栏先提示 /vabpnn start；按 F7/F8/F9/F10 会同时在聊天栏与底部行动栏提示结果及当前状态。提示跟随 Minecraft 语言，快捷键名称跟随实际绑定。F10 区分“请求后台保存”和“保存完成/失败”，同一保存请求完成前不会重复提交。GPU 尚未就绪时明确提示无法保存。可用 /vabpnn save 发起同样的保存。

按 T 输入 /vabpnn 或 /vabpnn status 查询模式、当前执行许可、已应用帧、15 路选中对象、按住的操作、GPU 算子最近/最大时间及超 10 ms 次数、处理/丢帧计数、有效示范及各头更新数、存档状态。聊天框本身会暂停模型操作，因此查询时“正在输入聊天，操作暂时停用”是正常状态。/vabpnn help 显示快捷键及命令。

底部状态每秒最多更新两次，显示模式、暂停/等待原因、人工或模型按住的操作和 GPU 算子时间；不会把每帧动作写进聊天记录。用 /vabpnn hud off 关闭实时底部提示，/vabpnn hud on 重新开启，热键反馈仍保留。模式/暂停提示至少保留三秒。HUD 开关仅在当前客户端会话内保留。

统计每秒最多读取一次 worker 已发布的 CPU 计数，显式状态查询立即刷新；保存请求/完成序号为主机元数据。反馈查询读取已完成快照，不触发 GPU 同步或图像回读。模型、连接、坐标支路和块级控制器统一使用上文的隔离预览存档。

## Minecraft 执行接入

GPU 后验与 k 选择（F8/仅预测绕过阈值拦截） → 40 字节 ControlCommand → 已完成 CUDA 事件的 JNI 回传 → ActionExecutor → Minecraft 26.1 KeyboardHandler / MouseHandler → 游戏移动、背包、视角、攻击/使用和快捷栏。正常启动处于待命；进入世界后 /vabpnn start 开始人工示范，F8 切换模型控制，F8 再次按下交还人工，F9 暂停。

- 1～5、13 分别发送原始 W/A/S/D/E/空格键。按住状态持续到下一次不再选择该键；E 使用按键上升沿打开/关闭背包。保留你指定的 W/S 和 A/D 可同时选择。
- 6/7 分别允许当前 GPU JEPA 输出的 X/Y 位移；仅应用一遍该帧位移。视角按原版灵敏度、反转和缓动处理。容器中同步更新 Minecraft 光标，再执行同包点击、拖动释放或滚轮。
- 8/9 为左/右键按下，10/11 为左/右键松开；按下保持直到对应松开或执行层停止。同一按钮的按下加松开仍产生一次合法点击。12 允许当前 GPU 滚轮输出，原版负责快捷栏或容器滚动。
- 每个游戏 tick 在读取玩家输入前检查许可及 0.5 秒指令租期，恢复模型拥有的按住状态，不重复制造点击。F8/F9、失焦、暂停、世界/界面/抓鼠模式变化均清空旧控制缓存，要求新场景的新 GPU 预测；单包中若 E 或回调改变场景，剩余操作停止。
- Minecraft 26.1 的 ToggleKeyMapping.release 不清点击计数，且 setDown 可能执行切换。执行层显式维护模型的按住/松开状态，停止时清掉它触发的待执行点击及界面恢复标记；人手仍实际按住的键/按钮保留。不会更改原版的切换攻击/使用选项。
- CaptureController.inputState() 在 Minecraft 线程提供只读执行状态：当前许可、已应用帧/掩码、模型拥有的键/按钮和累计应用次数；日志及实时窗口使用相同状态。

## 实时网络面板

沿用 AtomSpike 的独立深色 SNN scope 形式，执行 /vabpnn start 后默认显示，客户端启动时不创建窗口。DesktopScopeMixin 在 Windows 的 Main 静态初始化后恢复 AWT 桌面模式，解决原版设置 java.awt.headless=true 导致独立窗口无法创建的问题。不需启动 AtomSpike/Python，也不需要额外进程、网络服务或帧文件。F7 显示/隐藏，关闭窗口等同隐藏；退出游戏关闭窗口和计时器。窗口设置为不接受焦点，可置顶、拖动和缩放。游戏释放鼠标后才能点击面板（例如按 Esc）。

- 总览每格代表一个 16×16 神经元块，120×64 格覆盖固定 1920×1024 网格。显示平均膜电位，可点击右上角依次切换正负脉冲发放率和块级评分；这些是神经状态摘要，不是游戏画面。膜电位颜色相对基准阈值，不表示每个神经元经连接调制后的独立阈值。
- 点击总览选择块，再悬停或点击块内神经元，显示它当前最多四条实际出边。四类连接以不同颜色表示。总览绿点为实际高贡献节点，细线是最多 512 条实际长程边的抽样；没有绘制整个 86,784 条边集合。
- 光栅显示所选块的正负脉冲，青色正向、粉色逆向，每行汇总四个神经元，保留最近 180 次采样。脉冲余辉衰减用于视觉平滑，不是新增网络发放；10 Hz 观察可能漏掉两次采样间的瞬时脉冲。
- 15 项动作条展示贝叶斯后验、学习阈值、先验位置、原始有符号票数，以及 k/筛选结果。人工示范模式显示模型建议；模型控制模式额外显示实际执行包编号、已应用的许可和模型持有的按住状态。后验/票数来自低频 GPU 快照，执行状态来自最新已应用控制包，二者帧号可能不同。实际执行受输入许可和指令租期约束。
- 鼠标位移卡片显示人工输入、模型指令、模型执行各自的 **Δx / Δy**。约 30 Hz 汇总两次显示之间的位移，标注实际累计毫秒；单位是原始相对输入单位，不是角度或每秒速率。模型指令直接使用已有控制包（含 X/Y 许可和每帧 dt），同一包只统计一次；模型执行来自实际交付的视角输入或限位后的背包光标位移。空闲显示零，暂停、失焦和场景切换清空，超过 250 ms 没有更新也显示零。只交换六个主机标量，不添加 GPU 同步、图像读回、模型参数或训练更新。
- 块级控制器卡片显示当前开关和通信模式、所选块的四个实际控制量、评分、直接证据贡献、方向一致率和覆盖率，以及监督帧、策略更新、排名和变异计数。收到的是已完成帧的状态；命令提交与 GPU 实际生效分别反馈。
- 显示算子 last/max/超 10 ms 次数、连接/重连计数、示范/JEPA/位移训练步数、丢帧和模型内存。启动尚无数据、暂停和数据过期都有相应状态。

GPU 每 100 ms 最多汇总一次，单个只读快照 **165,376 字节**（约 161.5 KiB，约 1.58 MiB/s 主机流量）。完整游戏 RGBA/RGB、训练缓存和参数仍在 GPU；窗口只收到神经状态摘要、一个块的邻接信息及 15 路决策值。快照与该次完整预测具有相同 frameId，在 CUDA 事件完成后发布；渲染线程只读取已完成的主机快照，不等待 GPU。Swing 窗口约 60 fps 独立重绘，不访问 JNI 或 GPU 句柄。隐藏或暂停后不再汇总，不改变网络预测及学习次数。

开发时禁用自动弹窗：gradlew runClient -PnetworkScope=false；正式游戏 JVM 参数：-Dvabpnn.scope.enabled=false。之后仍可 F7 打开。相关源码为 client/scope/{NetworkMonitor,ScopePanel,ScopeSnapshot}.java 和 CUDAkernel 中的 NetworkScope.h/.cu。观测快照不进模型文件；持久化参数使用隔离预览存档，并通过旧版模型只读迁移保留原有学习结果。

## 连续显存流程

最终画面 → 自有 RGBA8 FBO 环 → GL 栅栏 → 共享 WGL 后台线程 → CUDA map / D2D → 有界线性池 → 块级控制器 → 同步 CSR / LIF 脉冲 → 像素投票 → JEPA 位移 → 秒制图 Transformer / 马尔科夫先验 / 贝叶斯后验 → k 与模式候选选择 → 15 路原子输入。

渲染线程只进行 blit 和提交。注册、映射、算子、训练和事件查询在 CUDA worker 上完成。纹理池和线性池默认各 4 槽，可设为 3～5；满时消费最新帧，丢弃尚未消费的旧帧，不回收在用资源。画面和表示张量不进入 CPU，不保存图片。主机交换真实输入元数据、40 字节最终控制包和训练计数；面板显示时额外接收上述低频神经状态摘要。

常驻模型及训练缓存共 **624,397,031 字节，约 595.5 MiB**，不包含 FBO、帧池和驱动临时内存。模型跨窗口尺寸变化保留；1920×1024 的帧池另按槽数分配。

## 像素神经元

固定 1920×1024 = **1,966,080** 个像素神经元。CUDA block = **16×16**，grid = **120×64**，共 7,680 块。

每像素、每 RGB 通道、每对象各一个权重，共 **88,473,600** 个 int8 三值参数。物理布局为 [channel][object][pixel]，用 weightIndex(p,c,k) 定位。每像素投 spike(p,t)*sign(R*wR + G*wG + B*wB)，其中 spike ∈ {-1,0,+1}，再累加全画面：

- 最终 15 项是原始 int32 总和，范围 ±1,966,080，**不再取全局 sign**。
- 输入尺寸不同时在 GPU 最近邻重采样，模型网格固定。
- 每 4 个有效示范执行一次局部监督更新：浮点潜在权重以像素 RGB 加权得到 logit，BCE 梯度作 SGD，基础学习率 0.02，乘所在块学习倍率 [0.8,1.2]，停用块级控制器时倍率为 1；潜在权重截到 [-2,2]，超过 ±0.05 分别量化为 ±1，其余为 0。
- 潜在参数额外占 337.5 MiB。推理仍只使用三值权重。
- 这是每像素的局部监督目标，**没有声称对硬 sign 或硬 top-k 做了端到端反向传播**。后续训练器仍可通过 MutableNeuronWeights 接入其他更新规则。

## 脉冲与稀疏连接

块内上限解释为每神经元 **4 条出边**；入边可超过 4。长程边独立计数。初始在各自 16×16 块中随机建立四条非自身、不重复的有向连接。人工示范模式每完成 5 次消费预测，在下一次预测前允许将出度改成 0～4，并重新选目标和四种属性；不按渲染帧或墙钟次数重连。重连时比较随机候选的贡献，偏向较高者。连接无需梯度训练。F8 评估时固定全部出边、CSR 与长程节点，只运行同步脉冲推理。

出边以 uint16 保存，每块最多 1024 条，转置为目标神经元分行的 incoming CSR：257 个 uint16 行偏移及最多 1024 个 uint16 源编号/属性。四种属性对应四个稀疏二值矩阵：

effect[k](t) = A[k] * abs(spike(t-1))

实现为一次按行 gather，同块上轮脉冲放入共享内存，再以总入度归一化四种作用。不会进行逐边主机处理或为每个块调用一次库。其行/列布局遵循 [NVIDIA CSR 定义](https://docs.nvidia.com/cuda/cusparse/storage-formats.html)。跨块 CSR 使用预分配 [CUB ExclusiveSum](https://nvidia.github.io/cccl/unstable/cub/api/structcub_1_1DeviceScan.html) 建行偏移，共用排序/扫描工作区。跨块每次预测同步计算，没有事件队列或活跃节点调度。

LIF 时间使用实际消费间隔秒数：decay=exp(-dt/tau)，v=decay*v+(1-decay)*luminance，默认 tau=0.035 秒，块级记忆倍率在 [0.85,1.15] 内调节该时间常数，停用时倍率为 1。四种连接属性仅影响下面四个方向，没有额外边权类别：

| 属性 | 作用 |
| --- | --- |
| 更容易被刺激 | 同时降低正、负发放阈值 |
| 更不容易被刺激 | 同时提高正、负发放阈值 |
| 更容易释放正向信号 | 单独降低正发放阈值 |
| 更容易释放逆向信号 | 单独降低负发放阈值 |

达到较低阈值时发放对应极性的脉冲，重置膜电位，进入默认 0.016 秒不应期；相同阈值选正向。下轮只读完整的上一轮脉冲，双缓冲避免块间读写竞争。静默神经元弃票，负脉冲反转该神经元的 15 项三值投票。首帧、场景复位、尺寸变化、时钟倒退和大于 0.25 秒间隔清掉瞬态活动；参数和贡献统计保留。非有限配置输出静默脉冲。

贡献使用与上一帧对齐的人工示范标签，模型控制模式不制造监督标签：

- 每神经元缓存 15 项实际发出的三值票，压到 uint32。设直接证据权重为 w[k]、该神经元票为 q[k]、像素数 N，delta=w[k]*q[k]/N。贡献以 BCE(z-delta,y)-BCE(z,y) 度量，再乘 N 做数值缩放，15 项取平均。这里固定其他图上下文和历史先验，属于对直接原始票数证据项的消融近似，不是逐像素重跑整个 Transformer。
- 人工示范期间最近投票的正、负、零 EMA 分布使用 decay=0.95；Shannon 熵除 log(3)，Simpson 指数 1-sum(p²) 除 2/3。交叉熵贡献和命中贡献也采用 EMA。
- 命中指选中且人工标签也为正的动作，保留正向票中的最大有效交叉熵贡献，并为每项动作归约最高贡献像素。负票正确抑制动作可得到交叉熵贡献，不计正向动作命中。
- 综合分数为 max(CE,0)*(0.5+0.25*H+0.25*D)+0.25*max(hit,0)。先纳入有效动作命中点，再从每块最高分候选中按分数选取，共 **最多 256 个**高贡献节点；该限制用于控制成本，并非全体像素两两连接。
- 高贡献节点形成双向有向团，每个节点还向 1≤|dx|+|dy|≤6 的全部有效邻居建立边，可穿过线程块边界。去掉自身和重复团边。容量最多 256*(255+84)=**86,784 条**长程边，边属性仍只有上述四类。人工示范、F8 连续控制和仅预测期间，贡献/分布统计继续更新，候选选点和两类拓扑每五次预测共同刷新。神经权重冻结独立于这些动态状态。

SNN 新增固定显存约 **125 MiB**，无每帧分配、CPU 图像复制或文件帧队列。贡献与拓扑参数会保存；膜电位、不应期、脉冲和票缓存不会保存。SpikeConnections.h 提供配置、贡献统计、出边和设备视图接口；外部修改必须在消费流上排队，遵守无自身/重复出边及四种属性的约束，修改出边后调用 RebuildSpikeLocalCsr。当前没有膜电位的替代梯度训练，已有局部三值权重训练与输出头 AdamW 保留。

## 时间图、贝叶斯和动作

图主干宽度 16、2 个注意力头、FFN 32、8 次消费帧的因果历史。时间使用秒制 dt、时间正余弦和 log 特征，历史投影使用当前参数重算。每个对象有独立两状态连续时间马尔科夫先验：

prior = rho + (previousPosterior-rho)*exp(-(on+off)*dt)，rho=on/(on+off)。

后验按 posterior = sigmoid(logit(prior)+conditionalEvidence) 更新；置信度采用该后验。15 个概率不要求总和为 1。人工示范预测保留学习阈值的筛选；F8 连续控制和仅预测不使用置信度阈值拦截。k 头有 0～15 的 16 类，选择概率最高的 k，再按对象后验排序，过滤明确互斥关系。

| 编号 | 操作 |
| --- | --- |
| 1 / 2 / 3 / 4 / 5 | W / A / S / D / E |
| 6 / 7 | 允许鼠标 X / Y 位移 |
| 8 / 9 | 鼠标左键 / 右键按下 |
| 10 / 11 | 鼠标左键 / 右键松开 |
| 12 | 允许垂直滚轮 |
| 13 | 空格 |
| 14 | Ctrl（疾跑） |
| 15 | Shift（潜行） |

互斥**仅**为 8–9、10–11、8–12、9–12。W 与 S、A 与 D、同一个按钮的按下和松开允许同时选择；后者按先按下再松开执行。

在线阶段沿用 AtomSpike 的“固定表示主干、学习输出层”思路：图 Transformer 主干和 CTMC 参数保持固定，AdamW 更新证据头（含本对象原始票数项）、阈值头和 k 头。证据头损失是给定历史先验的后验 BCE；阈值以 active=0.25、inactive=0.75 的软目标学习；k 用真实标签的对象数做交叉熵。图与 CTMC 的可写接口仍保留。模型的概率校准与实际决策能力需要游戏示范评估，尚无自主游戏奖励训练。

## JEPA 与位移

本工程的 temporal patch-MLP JEPA 从零初始化，不是下载的预训练 Meta 模型。

| 部分 | 参数 |
| --- | --- |
| 编码器 48 → 256 → 128 | 45,440 |
| 时间预测器 516 → 256 → 128 | 165,248 |
| 鼠标头 1169 → 256 → 2 | 300,034 |
| 可训练合计 | **510,722** |
| 加 EMA 目标编码器 | **556,162** |

30×16 patch 网格，各 patch 的 4×4 RGB 区域均值由 GPU 生成。在线编码器处理过去帧，预测当前帧的 EMA 目标表示；预测器不读取未来图像。人工示范模式每 4 次消费帧执行真实反向、AdamW 和 EMA；F8 评估时只计算表示与位移，不更新编码器、预测器、鼠标头及 EMA 目标。

自监督损失为 0.5*mean(prediction-target)^2 加 0.1*mean(max(0,0.2-std(pastLatents)))。AdamW 默认 lr=3e-4、beta1=0.9、beta2=0.999、eps=1e-8、weightDecay=0.01、梯度范数上限 1；矩阵衰减，偏置不衰减；EMA decay=0.996。表示质量仍需实测。

鼠标头以真实鼠标的**原始相对单位 / 秒**做监督 MSE，只更新头，编码器/预测器不接该任务梯度。模型控制时输出 tanh 限幅速度，最大 ±1200 单位/秒，按 dt 换成位移，每次上限 ±32；视角由 Minecraft 的灵敏度、反转和缓动处理，容器界面走窗口光标。滚轮另有小型监督头，输出垂直步数。动作 6/7/12 对应许可仍由贝叶斯决策控制。

## 示范对齐与保存

真实键盘按住时间、鼠标 X/Y 累计量、滚轮累计量及独立按下/松开计数随纹理槽发布，复制到对应线性帧后交给 GPU。丢帧不会清掉输入累计量。

观察 s(t) 保留在独立固定 GPU 缓存。下一次消费帧到来时，以这段间隔的真实输入训练缓存的 s(t)，然后才计算新帧。不是以动作造成的新画面反向标注同一动作。没有训练池裸指针跨帧使用。时间间隔须在 1～250 ms；模式/场景/焦点切换、非有限输入、过长间隔和倒退时钟拒绝配对。只有明确冲突的对象标签被拒绝，不增加额外互斥。视角与 GUI 光标切换时不构造跨模式鼠标目标。

保存由 worker 在当前算子完成后执行，只用固定 1 MiB 主机缓冲分块传送参数。保存期间 worker 暂停消费，游戏继续渲染，队列仍有界；模型控制可能短暂释放过期输入。文件含结构元数据与完整参数载荷 SHA-256，恢复验证全部内容后才修改 GPU 参数；临时文件完成后原子替换。缓存图像、激活和场景历史不写入文件。

AtomSpike 仅作为在线模式隔离、因果对齐和塑性参数保存的实现参考；没有引入它的 Python/CPU 图像链路，也没有改变用户指定的 15 路动作定义。

## 历史版本的 10 ms 预算与复现

0.9.0 保留与 0.8.0 相同的 CUDA DLL，SHA-256 为 D76B101803B6CD085266C98A6CF43026CCBA87E5E80ADD6D6274D2A7188BFEC7；以下 GPU 基准为该 DLL **开启可视化取样后的实测**。

本机 RTX 5070 Laptop GPU，Release/O3、1920×1024、64 帧预热、每档 512 帧；强制建立 256 个高贡献节点，最多 86,784 条长程边。每六帧执行一次完整 103,712 字节观测，模拟游戏 60 fps / 取样 10 Hz。下列时间是显存 D2D 复制、整个模型/训练、拓扑更新、观测汇总及控制/计数/观测 D2H 的 CUDA event 时间：

| 档位 | 平均 | 最慢 |
| --- | ---: | ---: |
| 推理，JEPA 自监督关闭 | 2.09 ms | 3.01 ms |
| 模型控制 + 每四帧 JEPA | 2.20 ms | 3.59 ms |
| 人工示范 + 每四帧 JEPA | 3.48 ms | 5.99 ms |
| 压力测试：JEPA 每帧，与像素训练/五轮重连重叠 | 3.94 ms | 6.68 ms |

四档共 2048 个测量帧未超 10 ms；压力档包含 25 帧拓扑、像素学习和 JEPA 同时执行，其中 8 帧也重叠观测汇总及 D2H，这 8 帧平均 6.25 ms、最慢 6.35 ms。实际长程容量由有效贡献选点决定，测试通过人工注入统计强制达到容量，用于测结构成本，不代表训练后的行为表现。

0.8.0 在真实 Minecraft 26.1 中完成 600 渲染帧启动/菜单验收：独立面板默认显示，F7 隐藏/恢复后继续收到有效 GPU 数据，恢复与保存 online-v2.bin、F8/F9/F10 及正常退出均成功，窗口和计时器随游戏关闭。日志记录算子最大 6.209 ms，超 10 ms 为 0；菜单未构造人工示范标签，完整示范训练成本由上表 GPU 基准覆盖。GPU 数值测试逐项核对全网格均值、所选块神经元/实际出边、长程抽样边与后验。真实 GL/JNI 测试确认隐藏停止取样而网络继续预测，以及更换选块后发布对应数据。

0.9.0 世界验收日志记录算子最大 6.642 ms，超 10 ms 为 0；当时包含人工模式在线学习和最多 256 个高贡献节点。该次验收关闭独立面板，开启取样的成本由上表覆盖。输入执行在游戏线程上完成，没有加入 GPU 等待或游戏帧 CPU 回读。

这不是全游戏帧时承诺：测试不包含 Minecraft 渲染、GL blit、GL/CUDA map/unmap、启动编译、模型存盘或操作系统调度。其他模组、GPU 竞争和电源模式可能使实际值超过预算。实际 worker 用 CUDA events 记录算子和控制回传耗时，日志每五秒报告 last/max/over10ms 及连接数量；通过有界池和丢弃旧帧保持渲染线程不等待网络。参数保存单独占用 worker，不属于稳态预测帧。

### 历史：0.9.5 工程效率优化

输出头保持原 AdamW 规则，按互不重叠的动作/k/滚轮参数并行更新，偏置校正每次训练只计算一次。块内 CSR 使用 [CUB BlockScan](https://nvidia.github.io/cccl/unstable/cub/api/classcub_1_1BlockScan.html) 计算整数行偏移；出边上限、五轮重连、四类属性和 SpMV 消费规则保持原样。检查点 worker 在没有到期或请求的存档任务时跳过重复检查。Java 侧避免相同面板状态的重复分配，以及 tick 中重复的输入场景校验。

CUDA 构建按翻译单元缓存目标文件，生产 GPU 架构和 sm_120 测试目标分开缓存。所有数值测试和基准复用测试算子，不再逐测试重编译整套算子。缓存校验源码、头文件、编译器/工具链、参数和目标文件 SHA-256；未改动的 DLL 不重复链接或复制。单独修改测试 .cu 不会触发生产 DLL 构建。

网络结构、参数数量、训练频率、默认示范模式、F8/F9/命令状态切换、显存链路、按键定义和模型存档布局均保持兼容。完整验证与性能对比见工程根目录的 ENGINEERING_OPTIMIZATION.md。
