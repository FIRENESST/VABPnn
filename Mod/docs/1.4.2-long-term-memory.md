# 1.4.2：时间关联的向量长期记忆

本版控制入口已精简：长期记忆随 start 默认开启，无单独 memory 命令；仅保留 start/stop/selftrain/explore 与 F7/F8/F9。两个监控默认隐藏，F7 统一开关；保存改由自动保存和退出完成。内部模型、检索与测试接口保留，旧检查记录中的命令指精简前版本。当前用法见 [模组说明](../README.md)。

这是正式版轻量图之外的经验检索模块，不使用 compare 的 7680×7680 全连接矩阵。像素算子仍为 1920×1024、线程块 16×16；秒 / 分钟图、PNN / CSR、模因、JEPA、动作阈值和 Scorer 自训练接口保留。

## 查询、融合和因果学习

`LongTermMemory.cu/.h` 自己持有固定容量 8192 的 64 维索引。每帧从 480×128 的 JEPA EMA 目标表征汇聚 32 个分量，附加 15 个归一化原始投票、8 个位置分量和 9 个秒 / 分钟 / 时间间隔编码，再归一化。没有画面 CPU readback、逐帧内存分配或外部网络检索。

每条记录以一 warp 计算精确余弦相似度；相似度至少 0.70、同一存档 / 维度 / 玩家、序号早于当前查询且有真实示范的记录，按余弦与时间保留评分进行精确 top-8。相同分数以槽号确定顺序。未标注观察走独立的新颖度检索，仅参与去重 / 写入。读取结果为带支持量的动作均值与 k 分布，经过读取门和有界 tanh 融合系数形成额外 log evidence / k logits。

融合在基础图与 CTMC / 分钟贝叶斯之后、最终动作阈值 / top-k 之前。最终贝叶斯后验也传给原 JEPA 残差头和鼠标轴门控；不会绕过学习阈值。Scorer 策略采样复用包含分钟、位置、记忆的固定 k 偏置，采样对数概率梯度与实际分布一致。

融合系数初始化为零。空库、无标签或不相似时原 DecisionOutput 保持逐字节一致；没有经验的模型不会立即获得游戏技巧。

有效人工示范仅能训练对应的上一帧 trace：帧号、模式、世界和生命会话均须匹配，且只消费一次。动作 BCE 与 k 交叉熵更新读取 / 融合参数；读 / 写 / 保留门的辅助目标分别依据示范损失改善、新颖度 / 基础模型误差和记忆标签质量。共 55 个可学习参数，AdamW lr=0.0003、β=0.9/0.999、weight decay=0.01，梯度限幅 1、权重限幅 8。已有基础模型梯度流程保持；这些新参数不加入奖励学习范围。

## 时间与身份

每客户端 tick 只采样两个 128 位身份和两个时钟；捕获帧固定对应的上下文，送入 CUDA。

- 世界身份由单人存档绝对路径或服务器地址、维度和玩家 UUID 派生；相同环境重启后稳定。
- 生命标识在玩家 / 世界对象变化时更新，死亡后先清空上下文；旧生命示范不会错误标注新生命。
- 单调纳秒时钟关联捕获帧与现有秒 / 分钟轴；上下文超过 250ms、倒序或重复帧不建立新查询。
- 经验保存秒数、分钟数、累计有效观察时间、UTC 创建 / 最近观察时间和生命元数据。年龄取累计观察差与非负 UTC 差中的较大值，长时间离线后仍能反映经验年龄。读 / 保留门输入含 log 秒龄、log 分钟龄以及秒 / 分钟相位差。
- 模式切换、重生和窗口重建清空 transient trace / 计时连接，不删除经验。不同世界隔离检索，同一世界跨生命保留长期经验。

同一存档移动到不同绝对目录会生成新的世界身份，旧文件保留，但不会自动混用两个目录的经验。

## 写入和冻结

相似度 ≥0.985 的观察复用记录，否则间隔至少 0.5 秒且写门 ≥0.45 才新建。满库每次最多扫描 64 个槽，以保留门、标签支持和访问统计进行有界替换，永远不超过 8192 条。记录只包含向量、真实示范动作均值、k 统计及时间 / 身份元数据。

| 模式 | 55 个记忆参数 / 优化器 | 真实示范标注 | 检索、年龄、访问、未标注新观察 |
| --- | --- | --- | --- |
| 默认人工示范 | 学习 | 开启 | 动态 |
| F8 模型控制 | 冻结 | 关闭 | 只读检索，持久状态冻结 |
| 仅预测 | 冻结 | 关闭 | 只读检索，持久状态冻结 |
| Scorer 自训练 | 冻结，仅原 1022 策略参数学习 | 关闭 | 只读检索，持久状态冻结 |
| memory off | 冻结 | 关闭 | 停止，已有记录保留 |
| 待命 / 暂停 | 不提交新帧 | 关闭 | 停止 |

冻结时不更改任何向量 / 标签 / k 分布、访问 / 命中 / 查询计数、创建 / 最近观察时间、累计观察时间、序号、替换指针或 catalog。查询仍使用当前秒 / 分钟和 UTC 计算相关性与经验年龄，但结果只在临时输出中，不写回记录。新颖度和写入停止；恢复人工示范后继续学习与写入。整个数据库在冻结前后重新保存，SHA-256 必须一致。PNN 高贡献点、CSR 和图的短期运行历史继续按原规则工作。

## 保存和兼容

- `vabpnn/models/release-1.4.2.bin`：v13 / VABPNNI、21 parts、522,118,564 字节。前 20 部分保留 v12 布局，末尾新增 672 字节 gate 参数、AdamW 一 / 二阶矩和步数。
- `vabpnn/memory/experience-v1.vdb`：独立 v14 / VABPNNJ、2 parts、3,866,944 字节，含 64 字节 catalog 与 8192×472 字节记录。完整 GPU 分配为 3,934,324 字节（含索引工作区、trace 和 scalar output；以程序报告为准）。
- 没有新 checkpoint 时，先只读继承 release-1.4.1.bin（v12），再沿原路径读 release-1.4.0.bin（v8）及旧正式版；不写回旧文件，不读取 compare。
- 模型和数据库分别采用现有 SHA-256 / 原子替换；自动保存及退出都处理两者。两个文件独立，单个文件的原子保存不等于跨文件事务；基础模型和索引可分别恢复。
- 损坏数据库不覆盖：只停用记忆，在状态中报告错误，基础推理和 checkpoint 保存继续。
- `vabpnn.model.path` 自定义模型默认派生 `.vdb`，`vabpnn.memory.path` 可指定独立路径；生产默认使用统一的 experience-v1.vdb。

## 检查入口

`gradlew.bat nativeMemoryTest` 检查满容量精确 top-8、去重、有界替换、世界 / 生命隔离、秒 / 分钟年龄、55 参数独立有限差分、冻结、SHA 校验，以及记忆证据到贝叶斯 / k / 阈值 / JEPA 鼠标的完整 GPU 链路。

`gradlew.bat nativeTest glCaptureSmokeTest` 运行全部原生回归和真实 OpenGL / JNI 保存恢复，包括 v12 只读迁移、新库重启、memory 开关和损坏文件保留。`runClientGameTest` 核对真实 Minecraft 的身份时钟、命令、人工标注、冻结及全部原操作。Scorer 独立测试保留实际执行回执、正负奖励、重生、手动接管、冻结和协议校验。

`gradlew.bat nativeRewardBenchmark` 在全部性能档中填充 8192 条有示范支持的记录，强制实际 top-8 和非零门控融合；和满 8 分钟槽、256 长程锚点、JEPA / 像素 / 模因 / 重连重叠、512 回执奖励更新一起测量。人为成熟 fixture 在计时事件外准备，不是训练结果；最终日志会打印 MEMORY_STRESS 确认检索没有退化为空库。

本次验证结果与部署清单由 `build/memory-1.4.2-validation.json` 记录。

已通过全部 20 个 CUDA 验证程序；55 个记忆参数独立有限差分最大误差 4.24e-8，原奖励策略的 1022 参数检查保留。真实 GL/JNI 的 MSAA0/4、v12 只读继承、v13+v14 重启及损坏文件保护通过。实际 Minecraft 的记忆命令、人工标注、F8 冻结与原 15 路操作通过；本轮普通游戏回归算子峰值 8.55ms，超过 10ms 为 0。

满 8192 条有标签经验、精确 top-8 且记忆融合非零的六档共 3072 帧独立 GPU 压测，复制 / 算子 / 小控制包读回合计最高 **8.3110ms**，超过 10ms 为 **0**。此值不包含 Minecraft 自身渲染，不是所有机器与后台负载下的硬实时保证。

Scorer 0.5.0 与 telemetry 0.5.0 的实际游戏闭环复测通过：正 / 负 / 死亡奖励更新 CUDA 策略；F8、仅预测、手动接管、重生、暂停和关闭自训练时，新增记忆参数和全部其他被冻结网络 / 优化器部分逐字节不变，检索与时间仍推进。实际鼠标视角回归同时通过前台 F8 转向、失焦建议可见但不注入、仅预测不转向及权重冻结。

2026-10-16 补充：上文独立 8.3110ms 压测属于精简控制 / 完整记忆冻结调整前基线。此次并行存在另一 Minecraft 客户端，仅作功能回归，不将竞争负载下的时间作为独立帧预算。当前版本新增整份向量库逐字节冻结与只读检索 / 恢复示范检查。

冻结档的压测向量只在预热时准备一次，正式计时期间不再由 fixture 改动；人工示范档仍在计时外构造满库匹配以覆盖检索压力。

最终补测（新冻结实现，六档 3072 帧）：满库峰值 **11.1636ms**，测试前后仍约 16% 后台图形 GPU 占用、926 MiB 显存，无 Minecraft / CUDA 计算进程。本轮 10ms 预算未达标，不用旧 8.3110ms 结果替代。冻结推理档最高 6.6280ms；全部原始压力数据保留在 `logs/validation/long-term-memory/controls-memory-freeze-final-build.log`，实际超时帧数见本次验证清单。
